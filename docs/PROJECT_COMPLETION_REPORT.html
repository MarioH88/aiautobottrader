1. Project Description

AI AutoBot Trader is an automated algorithmic trading system that processes live and historical market data, applies machine learning to predict short-term price direction, and executes trades through the Alpaca API. Unlike bots that rely only on static technical indicators, this system combines price action (RSI, MACD, ATR), news sentiment (Alpaca News + VADER), and macro mood (Kaggle-style CSV) to generate signals and dynamically size positions while managing risk with ATR trailing stop-losses.

Core capabilities implemented:

  • Async event-driven bot orchestrator (main.py → bot/trading_bot.py)
  • Alpaca REST market data ingestion (OHLCV bars) with optional WebSocket streaming
  • Random Forest / XGBoost direction classifier trained on technical + sentiment features
  • Automated order execution, position sync, and stop-loss management
  • Streamlit dashboard for portfolio monitoring, live prices, and manual trading
  • Backtesting pipeline and integration test suite

async def main() -> None:
    config = BotConfig()
    bot = TradingBot(config)

    if config.auto_start:
        write_flag(config.flag_file, "start")
        await bot.start()
        logger.info("[INFO] Auto-trading enabled — bot started automatically")

    await bot.watch_flag()

Listing B: bot/trading_bot.py — execution loop (data → ML → order)

async def execution_tick(self, symbol: str, from_stream: bool = False) -> None:
    sentiment, macro = self._combined_sentiment(symbol)
    frame = await self.data_pipeline.fetch_bars(symbol)
    bar_state = self.data_pipeline.latest_bar_state(frame, symbol, sentiment, macro)
    signal = self.strategy_engine.evaluate(bar_state)
    await self.execution_client.process_signal(signal, bar_state)

6. Challenges Encountered

Alpaca WebSocket connection limit — Running multiple bot instances exceeded Alpaca’s one-connection limit. Resolved by disabling WebSocket (USE_WEBSOCKET=false), using REST polling, and adding a circuit breaker to stop infinite reconnect loops.
ML overfitting / live mismatch — Models trained on historical data can fail in live markets. Mitigated with sentiment features, rule-based fallback when the model is unavailable, and backtesting before live use.
Fractional order errors — Alpaca rejected GTC orders for fractional shares. Fixed by using TimeInForce.DAY for fractional quantities.
Windows UTF-8 flag file — PowerShell wrote bot_control.flag with a BOM, causing start/stop commands to fail. Fixed with UTF-8-safe flag read/write utilities.
NumPy 2.x + pandas-ta — Technical indicator library broke on newer NumPy. Added a pure-pandas fallback in indicators_ta.py.
Live vs paper trading — Project spec targets paper trading; live keys require careful capital and risk controls. Documented in README and dashboard warnings.
