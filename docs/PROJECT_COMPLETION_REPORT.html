1. Project Description

AI AutoBot Trader is an automated algorithmic trading system that processes live and historical market data, applies machine learning to predict short-term price direction, and executes trades through the Alpaca API. The system combines price action (RSI, MACD, ATR), news sentiment (Alpaca News + VADER, crypto-alias aware), and macro mood (Kaggle-style CSV) to generate signals and dynamically size positions while managing risk with broker-backed ATR trailing stop-losses.

Core capabilities implemented:

  • Async event-driven bot orchestrator (main.py → bot/trading_bot.py)
  • Stock + crypto OHLCV (REST + WebSocket) with REST fallback
  • Random Forest / XGBoost direction classifier with rule-based fallback
  • Fractional allocation, broker stop orders, Discord alerts
  • Trading-window scheduler (overnight + multi-window)
  • Streamlit dashboard, Docker Compose, Windows/Linux deploy scripts
  • Backtesting with ATR exits + full integration/unit test suite

3. How the Bot Learns to Trade

The system learns offline, then applies that knowledge while trading. It does not automatically retrain after every live trade.

Training (learning step)

  1. Run python train_model.py
  2. Reads historical rows from train_data.csv
  3. Features: RSI, MACD, and sentiment_score
  4. Target: short-term direction — up (1) vs down (0)
  5. Fits Random Forest (default) or XGBoost and saves model.pkl

Live trading (inference)

  1. Fetch latest OHLCV bars (stocks and/or crypto)
  2. Compute RSI / MACD / ATR
  3. Score news with VADER and blend macro sentiment
  4. Ask model.pkl for a buy / sell / hold signal
  5. Allocation engine sizes the order (fractional when needed)
  6. Execution client places orders and manages ATR trailing stops

Fallback and improvement

  • If the model is missing/fails, RSI/MACD rules are used
  • To improve: expand train_data.csv, retrain, restart the bot
  • Validate with python backtest.py before relying on live results

Listing A: main.py — schedule-aware auto-start

async def main() -> None:
    config = BotConfig()
    bot = TradingBot(config)
    if config.auto_start:
        current = read_flag(config.flag_file)
        if current != "emergency_stop":
            write_flag(config.flag_file, "start")  # watch_flag starts the bot
    await bot.watch_flag()

Listing B: bot/trading_bot.py — execution loop (data → ML → order)

async def execution_tick(self, symbol: str, from_stream: bool = False) -> None:
    sentiment, macro = self._combined_sentiment(symbol)
    frame = await self.data_pipeline.fetch_bars(symbol)
    bar_state = self.data_pipeline.latest_bar_state(frame, symbol, sentiment, macro)
    signal = self.strategy_engine.evaluate(bar_state)
    await self.execution_client.process_signal(signal, bar_state)

7. Challenges Encountered

Alpaca WebSocket connection limit — Fixed with REST polling and a reconnect circuit breaker.
ML overfitting / live mismatch — Added sentiment features and rule-based fallback.
Fractional order errors — Switched fractional orders to TimeInForce.DAY.
Windows UTF-8 flag file — Built UTF-8-safe flag read/write utilities.
NumPy 2.x + pandas-ta — Added a pure-pandas fallback in indicators_ta.py.
Live vs paper trading — Prefer paper endpoint until validated; documented in README.
